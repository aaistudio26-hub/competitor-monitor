# Prompt Engineering Guide

## Где менять промпты

Редактируйте [backend/services/openai_service.py](../../backend/services/openai_service.py). `MARKET_CONTEXT` включён во все три сценария. В нём заданы четыре направления B2B-юруслуг, деловая аудитория и критерии конкуренции. Изменение общего контекста затронет также анализ сайтов.

| Параметр по коду | Анализ текста | Анализ изображения / PDF |
| --- | --- | --- |
| Метод | `OpenAIService.analyze_text` | `OpenAIService.analyze_images`; `analyze_image` передаёт один кадр |
| Модель | `OPENAI_MODEL`, по умолчанию `gpt-4o-mini` | `OPENAI_VISION_MODEL`, по умолчанию `gpt-4o-mini` |
| Вызов | `client.chat.completions.create` | Тот же метод с мультимодальным `user.content` |
| Параметры | `temperature=0.7`, `max_tokens=2500` | `temperature=0.7`, `max_tokens=2500`; `detail` для кадров не задан |
| Общая настройка | `OPENAI_BASE_URL` по умолчанию `https://api.openai.com/v1`. Ключ и модели задаются в локальной конфигурации, параметры генерации заданы в методах. | |

## 1. Анализ текста конкурента

**Вход.** Веб-маршрут `POST /analyze_text` принимает JSON с полем `text` от 10 символов. Схема не задаёт верхнюю границу длины. Метод передаёт текст в сообщение `user` после краткой инструкции. При текстовом запасном сценарии сайта `analyze_parsed_content` собирает title, H1 и первый абзац. Если все три пусты, он формирует результат с сообщением об отсутствии контента без вызова модели.

**Задача промпта.** Роль эксперта по конкурентному анализу, русский язык, строгий JSON, практически применимые рекомендации. Промпт указывает 3–6 пунктов для массивов. В `service_focus` допускаются только реально упомянутые направления. Если явно названа одна услуга, сохраняйте точность даже при конфликте с общей инструкцией о длине массивов.

| Тип в `CompetitorAnalysis` | Поля |
| --- | --- |
| Массивы строк | `strengths`, `weaknesses`, `unique_offers`, `recommendations`, `service_focus`, `trust_signals`, `content_gaps` |
| Строки | `summary`, `target_audience`, `positioning_notes` |
| Целые 0–10 | `trust_score` — доверие, `cta_score` — призыв к действию, `content_clarity_score` — понятность, `service_coverage_score` — покрытие четырёх направлений, `pricing_transparency_score` — цены/сроки/состав услуг, `competitive_threat` — конкурентная угроза |

**Когда качество падает.** Короткий текст, слоган без фактов, нерелевантная тематика и длинная страница с меню или юридическими оговорками усложняют выделение оффера. Проверяйте, что модель не приписала отсутствующие услуги, цены, кейсы и сроки. В исходном тексте могут встречаться инструкции, которые модель ошибочно примет за команду. Возьмите один такой пример в регрессионную выборку.

## 2. Анализ загруженных изображений и PDF

**Вход.** `POST /analyze_image` принимает один файл. Тип определяется по MIME или расширению. Для обычного изображения код передаёт один кадр. [pdf_service.py](../../backend/services/pdf_service.py) рендерит первые пять страниц PDF (или все, если их меньше) в PNG с масштабом 2.0. `analyze_images` принимает список пар `(base64, MIME)`, добавляет каждый кадр как `image_url` с data URL и при нескольких кадрах просит оценить их совместно. На файл приходит один общий результат.

**Задача промпта.** Роль эксперта по маркетингу B2B-юруслуг. Фокус на читаемости оффера, заметности услуг и воспринимаемом доверии. Ответ на русском, строгий JSON, 3–5 пунктов в массивах по инструкции.

| Тип в `ImageAnalysis` | Поля |
| --- | --- |
| Массивы строк | `marketing_insights`, `recommendations` |
| Строки | `description`, `trust_perception` |
| Целые 0–10 | `legal_branding_fit` — соответствие B2B-юрбренду, `service_visibility_score` — заметность услуг, `offer_clarity_score` — ясность оффера |

**Когда качество падает.** Мелкий шрифт, низкий контраст и плохой скан снижают читаемость. Цены, условия и кейсы после страницы 5 отсутствуют во входе модели. Для проверки нужного раздела подготовьте отдельный PDF или читаемый кадр. Неподдерживаемый формат, повреждённый PDF и ошибки провайдера диагностируйте отдельно от качества текста промпта.

**Соседний маршрут.** `analyze_website_screenshot` — самостоятельный промпт для `/parse_demo` и автосбора. Он принимает скриншот и контекст URL/title/H1/до 300 символов абзаца, использует vision-модель с `temperature=0.7`, `max_tokens=3500` и возвращает `CompetitorAnalysis`. При диагностике ошибок Vision на сайтах проверьте MIME: парсер получает PNG, а этот метод маркирует data URL как JPEG.

## Разбор результата и изменения

Веб-маршруты возвращают оболочку `success`, `analysis`, `error`. Поля таблиц находятся внутри `analysis`.

1. Текущий JSON-контракт задан инструкцией в промпте, без `response_format` в запросе. `_parse_json_response` извлекает блок кода или объект фигурных скобок, затем делает `json.loads`. При `JSONDecodeError` он возвращает `{}`. Сборщики подставляют пустые списки и строки. `_clamp_score` округляет числа, ограничивает их 0–10 и подставляет 0 при обычной ошибке преобразования. Некоторые несовместимые типы приводят к ошибке сборки модели. Поэтому HTTP 200 и `success:true` могут сопровождаться пустым анализом. Диапазон и число пунктов оценивайте раздельно.
2. Перед изменением зафиксируйте SHA, модель, параметры, изменяемую инструкцию и гипотезу. Сначала прогоните исходную версию. Меняйте одну вещь за итерацию и повторяйте измерение на тех же входах по [протоколу](03_SUCCESS_METRICS.md).
3. При изменении формата проверьте сборщик, [схемы](../../backend/models/schemas.py), [веб-рендеринг](../../frontend/app.js) и [desktop](../../desktop/main.py). При изменении `MARKET_CONTEXT` повторите также проверки анализа сайтов. После правки корневого backend синхронизируйте desktop и проверьте обе точки входа.
4. Предложения для следующей итерации: явно обозначить входные материалы как данные, требовать опору на видимое и разрешить пустые списки при нехватке фактов. Проверку исходного JSON и сигнал об ошибке нормализации оценивайте отдельным изменением. При регрессии верните предыдущую версию и повторите контрольный прогон.
